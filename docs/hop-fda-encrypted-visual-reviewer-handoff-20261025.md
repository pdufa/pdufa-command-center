# FDA visual page reviewer archive — controlled handoff protocol

**October 25, 2026 · Unmerged draft research. No human FDA source reviews completed.**

The repository `pdufa/pdufa-command-center` is **public**. Consequently, GitHub Actions artifacts and committed files are **not** acceptable destinations for the plaintext image/page mapping bundle. The existing research workflow renders 19 text-unextractable FDA PDF pages from the first 16 exact-hash reverified PDFs into **temporary private runner files**. No image files or page/application mappings have been published by that workflow. When the runner finishes, these private images are not durable.

## Newly implemented — encrypted handoff capability

`app/hop_fda_visual_handoff_preflight.py` checks **all 19** exact PNG names against two original private source manifests, original PDF fingerprints and individual PNG SHA-256 values. The files must be present together, unaltered, and explicitly marked **not reviewed, not verified, model ineligible**.

`app/hop_fda_visual_archive_crypto.py` creates a private ZIP **entirely in memory** and encrypts it using **AES-256-GCM** with a newly generated nonce and authenticated context. There is no plaintext ZIP uploaded to any artifact. The encrypted data includes only the 19 PNGs and their two private provenance manifests. Decryption requires the exact separately supplied 256-bit key, validates the authenticated tag, checks the 19-image count, matches all PNG SHA-256 digests and refuses duplicate or unexpected bundle paths.

`scripts/manage_hop_fda_encrypted_visual_handoff.py` supports private local encryption and reviewer-side decryption. It refuses to overwrite files, writes private outputs with restrictive permissions, and rejects placing decrypted images inside the public repository or public aggregate folder. It prints only counts and the unresolved-science status. Synthetic tests cover correct encryption/decryption, altered evidence, bad source hashes, missing images, malformed keys and modified ciphertext.

## Access controls and requirements

A reviewer archive can only be created on a machine or approved **controlled private job** that already has the 19 PNG files and their two private source manifests. The operator must generate a **fresh random 256-bit encryption key**, store it securely outside the repository, and provide it privately to an authorized reviewer using an independent secure channel. Never commit the key, include it in GitHub Actions logs or upload it alongside the ciphertext. A key in the same public folder as the encrypted artifact would defeat the intended access control.

Example for an authorized operator with the private image files already present:

```bash
# Do not paste or record the actual key into a GitHub issue or chat.
# In a private terminal, securely set the environment value to a
# unique 64-character hexadecimal string generated by a CSPRNG.
export PDUFA_FDA_REVIEW_ARCHIVE_KEY="(your privately supplied 64-hex-character key)"

PYTHONPATH=new-platform/backend python \
  new-platform/backend/scripts/manage_hop_fda_encrypted_visual_handoff.py \
  --encrypt \
  --private-image-dir /secure/source/no_text_visual_images \
  --private-batch1-manifest /secure/source/no_text_visual_manifest_batch1.json \
  --private-batch2-manifest /secure/source/no_text_visual_manifest_batch2.json \
  --encrypted-output /secure/transfer/fda_no_text_pages_19.aesgcm
```

The authorized recipient should place the ciphertext in a private work area and independently set the same key before decrypting:

```bash
PYTHONPATH=new-platform/backend python \
  new-platform/backend/scripts/manage_hop_fda_encrypted_visual_handoff.py \
  --decrypt \
  --encrypted-input /secure/transfer/fda_no_text_pages_19.aesgcm \
  --private-decrypted-output-dir /secure/recipient/fda_visual_review
```

These example paths are illustrative and are **not** claims that the current CI runner's transient files still exist.

## What is not installed yet

There is **no key configured or verified**, **no encrypted FDA image artifact uploaded**, no approved durable, access-controlled reviewer destination, and **no authenticated reviewer**. An encryption function and passing synthetic tests are not sufficient to claim working reviewer delivery. The GitHub PR CI deliberately does **not** use a repository secret or auto-upload ciphertext on `pull_request`, because code in an unmerged branch must not handle any stored reviewer key. Future storage access must be explicitly authorized, independently audited and set up for a **trusted workflow** after review.

Even a correctly decrypted PNG is only source evidence. Independent, qualified human review must verify the original FDA application identity, original vs supplemental action, date and actual regulatory review cycle. The published FDA CRL corpus is still incomplete as the national NDA/BLA decision denominator.
