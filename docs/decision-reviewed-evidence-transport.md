# Reviewed DECISION evidence transport

The authenticated, read-only `GET /api/decision-evidence/{programId}` connects an operator-supplied reviewed manifest to the existing research composer. Requests require the exact candidate key (`identity`), trial identifier (`trialId`), ticker and assessment stage (`stage`: PIPELINE, GEM_JR or GEM). Authentication uses the existing dashboard session. Responses are private and never cached. There are no write, import, scan-dispatch or order handlers.

The source is opt-in through the server-only `PDUFA_DECISION_EVIDENCE_DIR` environment variable. It must name an absolute directory containing files named `{programId}.{stage}.json`. This change neither sets that variable nor adds any evidence records. Missing configuration returns HTTP 503; an absent record returns 404; malformed, oversized or identity-mismatched records return 503. Errors do not disclose filesystem paths. Files are bounded to 2 MiB and final-component symlinks and nonregular files are rejected.

A file contains `schemaVersion: 1`, the full `identity`, `evidence` matching `ReviewedDecisionEvidence`, and the literal controls `researchOnly: true`, `modelValidated: false`, `probability: null`, `tradeAuthorized: false`. The response adds a SHA-256 digest of the original bytes for audit comparison. The parser validates every nested field consumed by the composer, bounds collections, rejects credential-bearing or non-HTTPS source links, and binds all records to the requested identity and stage. Unknown schema fields are rejected so a changed contract requires explicit review. Partial records can be transported; missing reviews and unsupported readiness still fail the existing evidence gates.

The optional `scienceDossier` carries the 20-level, 40-assessment, eight-layer source-cited inventory. Missing inventory remains unready. Optional `outcomeApplicationNumber` and `mainCompanyCik` explicitly record the reviewed FDA-application and company mappings; transport can carry absent/null or mismatched mappings so the composer can display the missing requirements. Integrated research review requires those mappings to agree with the dossier. They are declared mapping metadata and still require independent review against the original application, trial, indication, drug and issuer records; a matching string is not independent identity verification.

The digest establishes byte identity, not document authenticity. A reviewed flag, source URL, filename or valid schema does not independently verify a scientific report or FDA outcome. Operators must supply original reviewed sources and the actual predecision forecast/holdout record; the software does not create them. Synthetic regression fixtures cover transport and rejection behavior only. No prediction accuracy, membership change, FS/FA change, executable trading instruction or model validation is established by this endpoint.
